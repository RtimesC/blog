# 文章编写与编辑指南

本指南集中维护文章格式、写作约定、预览流程和 AI 编辑边界。字段校验实现见 [articles.js](../articles.js)。

## 最小示例

每篇文章保存为本目录中的一个 `*.article.md` 文件。以下仅为格式示例；标题、日期、关键词、素材和正文需由作者填写或确认。

```markdown
---
slug: my-note
publishedAt: 2026-10-01
title: "[文章标题]"
keywords:
  - "[关键词]"
cover: /assets/my-note/cover.png
---

## [章节标题]

[文章正文]
```

必填字段如下，正文也必须非空：

| 字段 | 规则 |
| --- | --- |
| `slug` | 全站唯一；只用小写字母、数字与单个连字符，对应 `/articles/<slug>` |
| `publishedAt` | 真实的 `YYYY-MM-DD` 首次发布日期，发布后保持不变 |
| `title` | 非空标题；直接说明核心内容，使用陈述式，产品介绍应明确产品名称 |
| `keywords` | 非空字符串列表；建议约 3 个稳定主题，把次要术语留在正文 |
| `cover` | 非空封面地址，用于首页；不会自动插入正文 |

## 可选字段与修订

```yaml
authors:
  - "[作者署名]"
abstract: "[作者提供或确认的摘要]"
revisedAt: 2026-10-02
```

`authors` 省略时不显示署名，提供时须为非空署名列表。`abstract` 省略时不显示摘要栏目，提供时须为非空字符串；首页不展示摘要。视频与参考文献格式见下文。

重要修订时手动设置 `revisedAt`，不得早于首次发布日期。首页按该日期（没有则用 `publishedAt`）倒序排列，同日按 slug 排序，每篇只出现一次；重要修订显示更新日期。错别字、措辞与排版修改不改变日期，不读取文件修改时间。

## 正文与媒体

正文自由组织，不强制固定章节。正文标题从 `##` 开始，按需使用 `###`，不跳级；不重复主标题、署名、摘要、关键词或参考文献标题，这些由页面生成。产品介绍先交代定位、核心机制与差异，再展开案例。

一段展开一个意思；粗体用于少量关键语句，并列事项用无序列表，有先后顺序的操作用有序列表。`>` 用于有来源的引用材料，链接文字应说明目标内容。短代码用反引号，多行代码用代码围栏。

素材放在 `public/assets/<文章标识>/`，正文引用 `/assets/<文章标识>/文件名`。图片放在相关段落附近、单独成段，填写有意义的替代文字；需要图注时使用紧随图片的独立斜体段落：

```markdown
![机械臂在桌面测试中抓取方块](/assets/my-note/grasp.jpg)

*桌面测试中的一次抓取。*
```

可选视频在摘要、关键词之后的正文区域显示，不自动播放；提供时 `src` 和 `poster` 都须为非空字符串：

```yaml
video:
  src: /assets/my-note/video.mp4
  poster: /assets/my-note/poster.jpg
```

当前支持基础 Markdown 标题、段落、列表、引用、图片、链接与代码，未接入 GFM 表格、任务列表、数学公式渲染或语法高亮。不要依赖原始 HTML 或水平分隔线排版。文件头部的 `---` 是元数据边界。

文章共用[阅读样式](../../styles/article.css)，具体视觉参数由代码维护；排版原则见[项目说明](../../../PROJECT.md#稳定原则)。

## 引用

有实际依赖的来源时填写 `references`，省略或留空列表时不显示参考文献栏目。条目内容由作者提供：

```yaml
references:
  - text: "[作者、文献标题、年份等真实书目信息]"
    url: https://example.com/source
  - text: "[真实纸本文献信息]"
```

`text` 必须非空；`url` 可省略，提供时只接受 HTTP 或 HTTPS 地址。上述地址仅作示例，数组顺序即编号顺序。

正文写 `[[1]](#ref-1)`，页面显示可点击的 `[1]` 并跳到文末第一条来源；普通文本 `[1]` 不自动转成链接。增删或重排来源时同时核对正文编号，标签与目标编号必须一致；不存在的引用目标会使文章加载失败。代码块中的引用示例也会被当前校验扫描，避免放入不存在的 `#ref-N` 目标。

## 草稿、预览与发布

1. 初稿保存在本目录之外；本目录没有草稿过滤，所有 `.article.md` 文件都会被加载，格式错误会阻止正常预览。
2. 准备预览时，将文章与素材放入对应目录，运行 `npm run dev`，访问 `/articles/<slug>`。
3. 作者核对标题、署名、摘要、关键词、正文、素材与引用，检查桌面、窄屏及明暗模式。
4. 作者明确决定发布后，按 [Git 速查](../../../GIT_WORKFLOW.md)操作。保存和 `npm run build` 不等于上线。

## 作者与 AI 的编辑边界

作者决定选题、署名、观点、事实、材料、来源、章节安排与是否发布。AI 在指定范围内修正文字、整理段落或检查格式；重要删改与章节调整先给建议，已明确授权的改写直接完成。

不补造经历、感受、实验结果、作者、机构或来源，不删除真实的不确定性。已实现、模拟演示与待实测的边界写在相关正文中，不缩成图注或免责声明。

内容编辑不包含共享模板、字体、宽度、栏目顺序、编号规则或 CSS 修改；视觉修改须有明确要求，变更后同步相关说明。“帮我编辑”也不包含提交、推送或部署。完成后说明修改范围与作者需要核对的内容，不自行标记视觉验收通过。

可直接使用：

> 按 src/content/articles/README.md，只编辑【指定部分】。保留我的观点和语气，不补造事实或来源；重要删改先给建议，不修改排版、不提交或发布。
